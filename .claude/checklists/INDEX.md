# レビュー修正パターン索引 (実装委譲コードのセルフレビュー規準)

出典: 実装エージェントへ委譲したコードに対するマージ前レビューの確定修正 54 件 (APKExplorer M3: 16 / M4: 13 / M6: 15 / M7: 10) + 以後の追記分。規則文は言語非依存 (スニペットは Python/PySide6 由来)。

**使い方 (implementer)**: この索引を読み、委譲プロンプトで指定されたカテゴリの詳細ファイル (同ディレクトリの `<番号>-<名前>.md`) を読んで従う。指定が無ければ作業内容に該当するカテゴリを自分で選ぶ。実装後のセルフチェックにも使う。プロジェクトの CLAUDE.md と矛盾する場合はプロジェクト側を優先する。

**運用 (メイン側)**: 新しいマージ前レビューで確定修正が出たら、該当カテゴリの詳細ファイルへパターンを追記し、この索引へ規則を一行追加する。§3・§4 の詳解やコード例を変更する場合は `references/` の同名ファイルも更新する。追記は必ずソース側で行う (CL_Orchestrator リポジトリ収容後は `checklists/` を編集して同期する — コピー同期環境で配置先へ直接追記すると次回同期で失われる)。

## 1. ネーミング — 詳細: `1-naming.md`
- 定数は SCREAMING_SNAKE_CASE + `Final` で宣言し、公開範囲を先頭 `_` で区別する
- PySide6 の API 名 (`Signal` / `Slot` / `Property`) を使い、PyQt 系の名前を持ち込まない
- camelCase は Qt オーバーライドに限定し、GUI 層の外へ持ち出さない (逆に snake_case へ「直さない」)
- シグナル名は snake_case の事象形、ハンドラは `_on_<シグナル名>` で統一する

## 2. 型ヒント — 詳細: `2-typing.md`
- 操作の由来など意味的な区別は、データ形状から推測せず判別フィールドとして型に刻印する
- 型情報を持たない外部ライブラリの戻り値は、境界層で自前の型付き不変モデルへ変換してから返す
- 欠落 (None) の扱いはフィールドごとに型で確定し、`str(value)` や暗黙変換で潰さない
- 型検査に不可視なペイロード (`Signal(object)` 等) は、受信時の isinstance ガード + 型付きアクセサで防御する
- テスト注入可能な呼び出し依存は `Callable[..., X]` ではなく Protocol で型付けする
- 型検査の抑止は「エラーコード付き・局所・最小限」に限定する

## 3. エラー処理 — 詳細: `3-error-handling.md`
- ファイルシステムの「チェック」と「使用」は 1 回の stat 系呼び出しに統合し、その呼び出し自体の失敗も翻訳する
- データモデルの不変条件は docstring で終わらせず、構築時検証で機械的に強制する
- ネストイベントループやモーダルを挟んで届くインデックス・参照は、受信時点の状態に対して再検証してから使う
- 既存ファイルへの上書き保存は一時ファイル+アトミック置換で行い、失敗時は元データを無傷で保全する
- 外部ライブラリの例外は境界層でドメイン例外へ翻訳し、捕捉順は継承関係を確認して決める
- 「パス or データ本体」の二形態引数は内容ベースで判別する (存在チェックで分岐しない)
- 共通ヘルパーへの置換は「契約の一致」を確認する — 旧コードの失敗様式を無音成功に変えない

## 4. テスト — 詳細: `4-testing.md`
- enum をキーとする辞書には集合比較の網羅性テストを置き、期待値は真の情報源と結合させよ
- 数値・長さ上限は「ちょうど = 合格」「+1 = 不合格」の対で検証し、超過時の伝播先仕様も固定せよ
- 多重防御の各層は、その層だけが反応する専用フィクスチャで独立に検証せよ (偽の緑の防止)
- 統合テスト・表示メッセージは存在確認ではなく、フィクスチャから導出できる正確な期待値で検証せよ
- property-based テストは、生成器が出力の全分類・実装の主要分岐に到達できる入力空間を張っているか確認せよ
- サニタイズ・無害化は、悪意入力をパイプライン全体に通して可視出力の全チャネルを走査するテストで検証せよ
- 代表 1 ケースで網羅を打ち切るな — 空コレクション・復路遷移・enum 全値をそれぞれ検証せよ
- カバレッジ等の品質閾値は実測値の直下でラチェットし、以後下げるな
- 品質ゲートの合否比較は表示丸めに依存し得る — 小数閾値には丸め精度を明示し、閾値未満で実際に落ちることを一度実証せよ

## 5. docstring — 詳細: `5-docstring.md`
- モジュール docstring に層の依存禁止事項を明記せよ
- 関数 docstring には型シグネチャの反復ではなく「型に現れない契約」を書け
- docstring に不変条件を書いたら、強制箇所を docstring 側にも明記せよ
- センチネル既定値・危険なフィールドの意味は定義位置で宣言せよ
- 意図的なコード重複・設計逸脱には理由を docstring に残せ

## 6. 依存方向 — 詳細: `6-dependencies.md`
- 下位層 (ロジック/モデル) から GUI フレームワークを import せず、境界はコールバックと標準型で設計する
- 依存方向ルールを lint + サブプロセステストの二段構えで機械的に強制する
- 推移的依存 (依存の依存) を自コードから直接 import しない
- 型なし外部ライブラリは境界モジュール 1 箇所に封じ込め、Any を上位層へ漏らさない

## 7. セキュリティ (信頼できない入力) — 詳細: `7-security.md`
- 危険文字の deny-list は「文字の列挙」でなく「脅威クラス」単位で洗い出し、全防御層を同時に更新せよ
- 「パスとして解釈しない」と「表示用に無害化する」は独立の防御 — 目視判断に使われる表示には必ず後者も適用せよ
- 種別フィルタの `continue` に危険検知の集計を巻き添えにさせるな — 比率の分子・分母は同一母集団で計算せよ
- 秘匿情報 (一時パス等) を消す「単一の関門」には、派生データへの複写経路と表記ゆれの全てを通せ
- リソース予算の会計は成功時の戻り値でなく実消費量を情報源とし、失敗経路も必ず通る場所に一本化せよ
- エントリ名からパスを導出する展開は「白リスト導出 + 封じ込め二重検証 + ソース再検証 + 実バイト上限」で書け — stdlib の extract/extractall を使うな

## 8. その他 — 詳細: `8-misc.md`
- 拡張子・ファイル名の判定は標準 API の慣習 (basename 単位・先頭ドットは拡張子でない) に揃えよ
- フィルタで除外したデータは無言で捨てず、除外件数を結果モデルに保持して UI で明示せよ
- 表示する数値に嘘をつかせるな — 丸め境界は繰り上げ、最終単位の飽和領域まで境界を張り、欠落値は欠落マーカーで示せ
- 状態切替時は前状態の表示残留を掃除し、その掃除が正当な表示を壊さないよう条件を絞れ
- 表示 API の解釈モード (リッチ/プレーン) をヒューリスティック任せにせず、エスケープと明示指定をセットで行え
- イベントループの再入 (非同期完了・モーダルダイアログ) を跨ぐ状態は、世代照合と同一性再検証で守れ
- 同名のシグナル/イベントでも発生源のスコープが異なるならハンドラを共有せず、対象範囲を明示的に渡せ
- 提出前に作業ツリーの衛生を確認せよ — ツール生成物の VCS 無視設定と、フォーマッタ整形後の可読性
- PowerShell ラッパで任意コマンドを素通しするなら「非 advanced スクリプト + $args」— CmdletBinding + ValueFromRemainingArguments は使わない
- 表示・出力用のパス表記を内部の索引キーに流用するな — 異なる実体が同じ表記へ潰れる
